# Agent Action Evals v0.2.0a1

First public alpha, released 26 September 2026.

Fault-injection testing for tool-using AI agents: run an agent against simulated
business state, inject tool failures, and check the effects of its actions.

## Highlights

- **Reusable refund pack:** 14 cases covering authorization, eligibility,
  existing refunds, stale reads, read failures, and safe refund recovery. Bind
  your own tool names, schemas, handlers, and state paths.
- **Automatic fault cases:** generate independent timeout, lost-response, and
  stale-read variants at declared tool-call positions. Cases explicitly fail
  coverage checks when their intended injection never fires.
- **Readable failure evidence:** timelines distinguish attempts, effects, and
  observations. Findings link to recorded events, with rerun commands and
  payload redaction enabled by default.
- **Python and LangGraph examples:** offline scripted policies work without
  model credentials. An opt-in live LangGraph example is also included.
- **CI output:** versioned JSON, JSONL checkpoints, JUnit, text reports,
  preflight validation, configuration hashes, and explicit CLI exit codes.
- **Execution options:** trusted in-process and subprocess adapters, plus an
  offline Docker adapter with resource and filesystem/network restrictions.

## Install

Requires Python 3.11 or newer. Install the wheel attached to this GitHub release:

```bash
python -m pip install https://github.com/pratik-mahalle/agent-action-evals/releases/download/v0.2.0a1/agent_action_evals-0.2.0a1-py3-none-any.whl
```

To run the included examples, use a checkout of the release tag:

```bash
git clone --branch v0.2.0a1 --depth 1 https://github.com/pratik-mahalle/agent-action-evals.git
cd agent-action-evals
python -m pip install -e .
agent-action-evals examples/refund_pack.py --repeat 2 --text refund-report.txt
```

Expected: **28/28 passing runs** from the synthetic Python refund example.

For the offline LangGraph version:

```bash
python -m pip install -e '.[langgraph]'
agent-action-evals examples/langgraph_refund_pack.py --repeat 2
```

Expected: **28/28 passing runs**. These policies are scripted; the results do
not measure live model quality.

## Included assets

- `agent_action_evals-0.2.0a1-py3-none-any.whl` — installable Python package.
- `agent_action_evals-0.2.0a1.tar.gz` — source distribution, including examples
  and documentation.
- `SHA256SUMS` — checksums of the wheel and source distribution.

After downloading all three files, verify the assets with `sha256sum -c
SHA256SUMS` on Linux or `shasum -a 256 -c SHA256SUMS` on macOS. On PowerShell,
compare `Get-FileHash <asset> -Algorithm SHA256` with the corresponding entry.

## Validation

- 74 local tests passed; two Docker tests were skipped locally because no
  Docker daemon was available.
- Hosted CI passed on Linux, macOS, and Windows, including Python 3.11–3.14
  coverage and the real Docker boundary/cleanup checks on Linux.
- The reusable pack passed 56/56 offline executions: 14 cases, twice each
  with the Python and LangGraph scripted policies.
- A deliberately broken retry policy produces a duplicate refund that is
  attributed to its second committed refund.

The repository's [CI runs](https://github.com/pratik-mahalle/agent-action-evals/actions/workflows/ci.yml)
provide the build and test evidence.

## Alpha limitations

- Live-model benchmarking, production-agent pilots, and external-team setup
  studies remain pending. The recorded scores cover synthetic fixtures and
  scripted policies.
- This release includes one domain pack: refunds. Other domains can use the
  generic scenario and fault-generation APIs.
- Fault generation uses authored expectations and declared call positions.
  It does not infer business correctness or automatically discover agent paths.
- Scenario definitions and handlers are trusted Python. In-process timeouts
  are cooperative; broader adversarial and production isolation review remains
  open.
- A rerun reuses the scenario and seed; live model output can still vary.
- The API remains alpha. JSON reports use a versioned envelope containing
  `summary` and `runs`; drivers receive `ToolClient`, not the internal `ToolPort`.

See the [scenario-pack guide](https://github.com/pratik-mahalle/agent-action-evals/blob/v0.2.0a1/docs/SCENARIO_PACKS.md)
and [report contract](https://github.com/pratik-mahalle/agent-action-evals/blob/v0.2.0a1/docs/REPORTS.md).
