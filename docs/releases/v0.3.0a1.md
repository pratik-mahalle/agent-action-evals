# Agent Action Evals v0.3.0a1

**Test existing tools.** Alpha prerelease, 26 September 2026.

Wrap existing Python functions and LangGraph tools, inject failures at their
boundary, and inspect what the agent does next. Recovery stays with the agent.

## Highlights

- **`ToolBoundary.wrap()`** supports synchronous and asynchronous functions,
  preserving normal inputs, outputs, signatures, and original exceptions.
- **`wrap_tool_node()`** uses native LangGraph hooks to retain tool schemas,
  runtime injection, configuration, artifacts, and `Command` outputs.
- **Ambiguous failures:** inject a timeout before execution, discard a result
  after the callable returns, or substitute a stale read. Before/after timeouts
  expose the same exception to the agent; the evaluator retains the fault label.
- **Trace recovery:** record calls, repeated inputs, observations, cancellation,
  duration, and fault coverage. Concurrent calls stay concurrent. The boundary
  performs no automatic retries or deduplication. Payload capture is opt-in.
- **Optional outcome verification:** `execute_verified()` checks correlated
  status receipts against declared effects, with bounded recovery and retries
  that require an explicit service idempotency guarantee. This helper is separate
  from the thin wrapper and is not required to test existing tools.
- **Examples and evidence:** a local SQLite write/response-loss example, twelve
  synthetic verification cases in Python and LangGraph, and a recorded live
  Jev/custom-D1 integration check.

## Install

Requires Python 3.11 or newer. Install the wheel from this GitHub release:

```bash
python -m pip install https://github.com/pratik-mahalle/agent-action-evals/releases/download/v0.3.0a1/agent_action_evals-0.3.0a1-py3-none-any.whl
```

For the examples and optional LangGraph integration:

```bash
git clone --branch v0.3.0a1 --depth 1 https://github.com/pratik-mahalle/agent-action-evals.git
cd agent-action-evals
python -m pip install -e '.[langgraph]'
python examples/wrapped_sqlite_tool.py
```

Expected: the caller sees a timeout, while an independent query finds exactly
one committed note. The wrapper does not retry. This example is local and needs
no model credentials.

## Wrap your existing tool

Given your existing `create_issue` function:

```python
from agent_action_evals import Fault, ToolBoundary

boundary = ToolBoundary(
    (Fault("create_issue", "response_lost_after_commit", on_call=1),)
)
tested_create_issue = boundary.wrap(create_issue)

# Register tested_create_issue with your agent in place of create_issue.
# After the agent runs:
report = boundary.report()
```

For existing LangGraph tools, use `wrap_tool_node(existing_tools, boundary,
**your_node_options)` from `agent_action_evals.adapters.langgraph`. Both sync and
async graph execution are supported. The
[tool-boundary guide](https://github.com/pratik-mahalle/agent-action-evals/blob/v0.3.0a1/docs/TOOL_BOUNDARY.md)
documents usage, tracing, and limits.

## Validation and benchmark scope

- **130 local tests passed; 3 skipped.** The skipped checks require the optional
  upstream comparison checkout or a Docker daemon. Nineteen new checks cover
  the Python boundary and execution inside real LangGraph graphs.
- Ruff checks and formatting passed. Wheel and source distributions were built;
  the installed wheel's public API and SQLite example were checked.
- Publication is gated on the repository's hosted CI matrix, covering Linux,
  macOS, Windows, Python 3.11–3.14, the Linux Docker checks, and the pinned
  comparison suite. See the [CI runs](https://github.com/pratik-mahalle/agent-action-evals/actions/workflows/ci.yml).
- The scripted verification benchmark passed 120/120 authored runs per verified
  adapter. This is synthetic conformance evidence.
- The live Jev `1.13.0` / Cloudflare D1 run contained 36 trials. Verification
  passed 18/18 trials with zero false success claims; direct tool use made three
  factually false claims. All 36 recorded states matched an independent D1 query.
  The temporary cloud resources were deleted afterward.

The live service was a custom synthetic refund ledger. No money moved, and no
payment provider was tested. Those measurements predate release packaging; their
original versions, source hashes, failures, and limits are preserved in the
[live report](https://github.com/pratik-mahalle/agent-action-evals/blob/v0.3.0a1/benchmarks/results/live-jev.md).
The three false claims and fifteen unverified claims in the direct policy are
overlapping metrics, not eighteen separate business failures.

## Compatibility and limits

- The API remains alpha. Existing simulated scenarios and report contracts remain
  available. `ToolBoundary.report()` is a standalone trace, not a runner verdict.
- For real callables, `response_lost_after_commit` means after the callable
  returns. A separate service read must establish whether a remote effect committed.
- The boundary is trusted in-process instrumentation. It observes registered
  calls; SDK-internal retries and calls that bypass it are outside its scope.
- Streaming generators need a separate boundary and are rejected. Use a fresh
  boundary per evaluation run; traces are retained in memory for that run.
- The LangGraph wrapper requires ToolNode's sync and async wrapper hooks. It was
  checked with LangGraph 1.2.12 / langgraph-prebuilt 1.1.0; unsupported versions fail
  setup with an update message.
- Native GitHub/other service packs, independent external-state observer
  integration, and production-team pilots are the next milestones. This release
  does not establish broad production reliability.
